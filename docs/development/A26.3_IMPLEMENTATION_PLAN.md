## Objective

Implement the TMDB provider adapter that connects WatchLog's provider-neutral streaming-availability domain to TMDB movie and TV watch-provider endpoints, without introducing UI, persistence, caching, startup fetching, or changes to the A26.2 availability domain.

## Baseline

A26.1 region preference and A26.2 streaming-availability domain/foundation are treated as the verified baseline. A26.3 consumes the existing provider-neutral contracts and existing TMDB request infrastructure.

## Architecture Decisions

1. **Adapter location:** `src/services/tmdb/tmdbAvailabilityAdapter.ts`.
2. **Supporting TMDB service:** `src/services/tmdb/tmdbAvailabilityService.ts` between the adapter and `tmdbRequest`.
3. **Response contracts:** `src/services/tmdb/tmdbAvailabilityTypes.ts`.
4. **Tests:** `src/services/tmdb/tmdbAvailabilityAdapter.test.ts`.
5. **Exports:** update `src/services/tmdb/index.ts` only when the implementation requires it.
6. **Provider keys:** adapter/capability/result use `"tmdb"`; each TMDB provider offering uses `"tmdb:" + provider_id`.
7. **Provider label key:** offering label key is structurally `"provider.tmdb." + provider_id`; localization resolution is outside A26.3.
8. **Region handling:** pass the explicit `AvailabilityRegionCode` to the adapter and select `results[region]`; do not add a TMDB `region` query parameter to the watch-provider endpoint.
9. **Media identity:** obtain the TMDB ID from the existing `ExternalIdType.tmdb` identity data and branch between movie and TV endpoints.
10. **Timeout/retry:** no adapter-owned timeout or retry. Application/service orchestration owns timeout configuration.
11. **Offline behavior:** preserve the existing availability service offline short-circuit; A26.3 must not add its own network lifecycle.
12. **404:** resolve as an empty availability result because the current domain cannot distinguish an unknown TMDB title from no providers for the region.
13. **Other HTTP failures:** 429 maps to rate-limited; 5xx maps to service-unavailable; network/timeout handling remains aligned with the existing service/error model.

**Status:** IN PROGRESS

**Scope:**

- Represent the response envelope, region-keyed results, provider entries, and provider offering groups required by A26.3.
- Keep these types TMDB-specific and separate from provider-neutral domain types.

- `src/services/tmdb/tmdbAvailabilityTypes.ts`

## Performance Guardrails

- No availability calls on application startup.
- No whole-library availability fetching.
- No dashboard-wide bulk availability requests.
- No background polling or refresh loops.
- No A26.3 caching or persistence.
- One TMDB request per explicitly requested media item.
- Reuse the existing availability-service orchestration and offline short-circuit.
- Do not add adapter-owned timeout/retry behavior.
- Do not add new dependencies or architectural layers.
